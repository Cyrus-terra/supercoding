# supercoding

[English](README.md) | **简体中文**

**为 AI 编码助手提供跨语言工程规范，把复用、清晰边界和性能意识带进每次开发。**

supercoding 是一个 **Agent Skill**，覆盖架构、接口、异步状态、页面、后端数据和验证中的关键编码决策。指导助手关注一次改动如何融入现有项目、如何应对失败，以及数据增长后的成本，而不只看新增代码能否运行。

**一个轻量入口，八份按需参考，沿用你的技术栈和项目规范。** 仓库提供 Claude Code、CodeBuddy、Codex、Gemini CLI、Hermes Agent 和 OpenClaw 的原生插件/扩展封装。

## 核心能力

这些规则关注容易让“功能可用”演变成维护、正确性或性能问题的开发决策：

| 开发中遇到…… | supercoding 指导助手如何处理 |
| --- | --- |
| 业务逻辑重复、模块耦合、公共组件不断膨胀 | 先找已有能力，按职责划分边界，共享稳定规则，保持调用契约；让抽象规模匹配实际复用需求。 |
| 列表慢、接口返回过大、细碎请求过多 | 区分查询、传输和渲染成本；使用服务端分页与必要字段；根据使用时机和成本选择拆分、聚合或有上限的批量请求。 |
| 旧结果覆盖、loading 不结束、重复提交 | 明确数据、loading 和错误的操作归属；防止乱序完成污染当前状态；处理取消、防重与资源释放。 |
| 新增控件挤坏原页面、影响其他区域 | 复用设计系统和局部样式；沿实际操作路径检查换行、长内容、浮层、焦点及失败重试。 |
| 大文件、无上限任务、返回错误数据的缓存 | 限制已提交任务和输出缓冲，全链路流式处理；定义缓存键和失效规则，保持租户与权限边界。 |
| 凭猜测修复、重构改变行为、评审建议相互冲突 | 用实验区分原因，保持可观察行为与副作用，根据契约核实反馈，并如实报告实际获得的证据。 |

这些是按条件采用的工程判断。缓存、懒加载、组件提取和接口拆分都需要具体依据，不是每个任务都机械执行的改造清单。

## 一次功能开发中的完整考虑

**需求：给已有订单页增加状态筛选。**

规则将这次改动涉及的多个环节联系起来：

1. **复用项目已有能力。** 先看现有筛选区、请求层、表格和接口，再决定是否新增组件或请求封装。
2. **保持查询行为一致。** 协调状态条件、分页和适用的选择规则，检查后端是否按条件筛选并分页返回数据。
3. **保护当前状态。** 快速切换条件时，旧响应不能覆盖当前结果、显示过时错误，或提前清除新请求的 loading。
4. **控制数据成本。** 列表只返回摘要字段，大详情打开时再加载，检查直接受影响的查询是否存在逐行请求和无效工作。
5. **融入原页面。** 检查新增筛选与已有操作的关系，包括长标签、最窄支持宽度、loading、空结果及重试反馈。
6. **验证完整操作路径。** 快速切换筛选、翻页、复现失败后重试，并确认原有控件仍能正常使用。

这是规则指导范围的示例，不是已测得的模型效果。根据实际任务选择相关检查；仅授权前端修改时，应指出范围外的后端需求，不擅自扩大改造。

同样的思路也适用于页面之外：CSV 任务需要限制并发并保持输出顺序；公共函数需要核对调用方和副作用；数据库变更需要考虑一致性和部署影响。

## 适合日常开发的使用方式

- **按需加载上下文：**先使用入口，再读取当前功能所需参考；上下文中完整且未变化的规则直接复用，微小修改可以只用入口。
- **结合项目复用：**沿用现有语言、框架、请求基础设施和设计系统，检查相关旧代码，对新增与修改部分应用规范。
- **保持改动聚焦：**精简职责和重复逻辑，同时保持契约；不把无关清理和假想框架混入当前需求。
- **根据证据验证：**按风险选择检查，区分性能实测、行为测试通过、静态推断和未验证结果。
- **与专项规则协作：**结合可用且相关的专项 Skill，避免重复流程。不同语言任务共用英文规则，回复跟随用户偏好。

纯 README、文档编写、翻译和普通交流不触发。supercoding 不额外强制需求访谈、设计文档、TDD、多代理、worktree 或审批流程，已有项目流程仍按项目要求执行。

## 快速开始

每个客户端选择**一种**原生插件/扩展或独立安装。各客户端共用同一套运行规则；通过支持的客户端使用 DeepSeek 等模型时，安装格式不变。

### 安装

安装受管理的独立副本时，先获取源码，使用 Python 3.9+ 安装。以下以 Codex 为例：

```sh
git clone https://github.com/Cyrus-terra/supercoding.git
cd supercoding
python3 -B scripts/manage.py install --client codex --source .
```

没有 Python 时，可将完整 `skills/supercoding/` 复制到客户端技能目录，保留已有安装。各客户端的插件和独立安装说明：

| 客户端 | 可用安装方式 | 安装指南 |
| --- | --- | --- |
| Claude Code | marketplace 插件、本地会话插件、独立 Skill | [Claude Code](docs/clients/claude-code.zh-CN.md) |
| CodeBuddy | marketplace 插件、本地会话插件、独立 Skill | [CodeBuddy](docs/clients/codebuddy.zh-CN.md) |
| Codex | 仓库 marketplace 插件、独立 Skill | [Codex](docs/clients/codex.zh-CN.md) |
| Gemini CLI | 原生扩展、独立 Skill | [Gemini CLI](docs/clients/gemini-cli.zh-CN.md) |
| Hermes Agent | 原生插件、独立 Skill | [Hermes](docs/clients/hermes.zh-CN.md) |
| OpenClaw | 原生插件、独立 Skill | [OpenClaw](docs/clients/openclaw.zh-CN.md) |

默认路径、Windows、项目级范围和排错见[共用安装指南](docs/installation.zh-CN.md)。本仓库提供封装，但不宣称已进入官方市场、npm 或 ClawHub。实际集成证据和限制见[客户端验证矩阵](docs/installation.zh-CN.md#验证证据)。

### 使用

新建客户端会话，确认 `supercoding` 或 `supercoding:supercoding` 可用，然后尝试：

```text
使用 supercoding 给已有订单页增加状态筛选。
遵循项目现有规范，验证受影响的行为和页面布局。
```

也可以用于：

- “排查为什么切换筛选后，搜索结果偶尔会跳回旧条件。”
- “重构这段重复业务逻辑，保持原行为和副作用。”
- “评审这次接口改动，关注多余数据、查询成本和调用方兼容。”
- “让这个大文件任务在有上限的内存和并发下处理数据。”

发现 Skill 不等于每次编码都会使用。需要默认使用时，将[编码指令](docs/installation.zh-CN.md#所有编码任务默认使用)加入客户端实际加载的上下文文件。

## 旧项目与执行范围

在客户端系统、安全和权限约束内，用户明确要求与项目明确规范优先于通用 Skill。已有代码为一致性提供参考，已有缺陷不会因此成为应当复制的规范。

打开项目不会自动审计。编码时只检查相关代码；全面审查需要明确提出，仅授权审查不等于授权修复。Skill 不是 MCP 服务，也不授予安装依赖、推送、部署或外部发布权限。

## 更新

原生插件/扩展通过客户端更新，自动升级取决于宿主配置。会话 Hook 只提供本地提醒，不联网拉取更新。

受管理的独立副本支持只读检查与预览、完整目录备份、自定义内容保护和回退。在源码目录执行：

```sh
python3 -B scripts/manage.py check --client codex
python3 -B scripts/manage.py update --client codex --dry-run
```

联网检查需要对应的稳定 GitHub Release。没有可用 Release 或离线使用时，加 `--source .` 从可信本地源码读取。执行更新前先阅读[更新与恢复指南](docs/installation.zh-CN.md#版本检查更新和回退)。

规则和工具变化见 [CHANGELOG（英文）](CHANGELOG.md)。正式发布前，不同源码修订可能使用相同版本号，应结合 commit、文件变化和版本标签判断。

## 验证

仓库包含确定性打包/更新测试，以及五组可运行案例与正确对照：搜索乱序、有上限的 CSV 流式处理、尾批丢失调试、行为保持重构和混合评审反馈。

在仓库根目录执行：

```sh
python3 -B scripts/validate_skill.py
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
python3 -B scripts/run_examples.py
```

这些检查验证包和评测工具的行为，不能证明自动触发、模型输出改善、视觉正确性或性能提升。成功的真实模型对照、远端 CI 和 Windows Hook 启动仍未验证，详见[客户端证据矩阵](docs/installation.zh-CN.md#验证证据)与[评测协议及实际记录（英文）](tests/evals/protocol.md)。

贡献应对应具体失败场景，提供可观察的评测证据，并保持按需加载。详见[维护指南（英文）](docs/development.md)。README 和安装说明双语，运行规则、维护及评测材料保持英文。
